# Feature: ARD-Manifest und llms.txt statt eigenem Format

Dashboard-Task #1430 (ai-manifest), Ursprung #1418. Entscheidung: `.project/doku/decisions/0001-ard-statt-eigenem-format.md`.
Risiko: kritisch — öffentlich erreichbare Landkarte der Oberfläche, neue Routen, Schnittstellenbruch (Major). Spec selbst freigegeben (automode 2026-11-17-0939).
Rückbau: #1433 (PageSpeed Insights bewertet `ard.json`; dann entfällt `/.well-known/ai-catalog.json`)

## Ausgangslage
Paket 1.x liefert `GET /.well-known/ai-manifest.json` (eigenes Format: Kopf mit Name, Auth, Mechanismen, `capabilities`). Lighthouse (Kategorie „Agentic Browsing“) prüft stattdessen `ard-schema` (ARD v0.91: `/.well-known/ard.json` oder `rel="ard"`) und `llms-txt`. Der Konformitätstest von Lighthouse 13.6.0 (`third-party/ard/ard.js`) liegt lokal vor: Pflicht ist `entries`; je Eintrag `identifier` (`urn:air:<publisher>:<namespace>:<name>`), `displayName`, `type`, genau eines von `url`/`data`; `representativeQueries` mit 2–5 Zeichenketten (sonst Warnung); Medientyp `application/*` außerhalb der Standardliste nur Hinweis, andere Typen Warnung. `llms-txt` verlangt Markdown mit H1 (`# Titel`), mindestens 50 Zeichen und mindestens einen Link `[x](y)`; bei 4xx ist das Audit „nicht anwendbar“.

## Akzeptanzkriterien
- **AK1 — ARD-Route:** Gegeben die Standard-Config — Wenn `GET /.well-known/ard.json` — Dann Status 200, Header `Content-Type: application/ai-catalog+json; charset=utf-8`, Body ein JSON-Objekt mit Liste `entries`; Routenname `ai-manifest.ard`. Die Route `/.well-known/ai-manifest.json` (Name `ai-manifest`) gibt es nicht mehr (404). `middleware` aus der Config gilt für alle Routen des Pakets (ARD, Übergangspfad, llms.txt).
- **AK2 — Eintrag je markierter Route:** Gegeben Routen mit `->aiManifest()` (und Einträge der Generatoren `AiManifest::addGenerator`) — Dann hat jede einen ARD-Eintrag: `identifier` = `urn:air:<publisher>:<namespace>:<id>` (Zeichen der `<id>` außerhalb `[A-Za-z0-9._-]` werden je durch `-` ersetzt), `displayName` = `summary`, ohne Summary die `id`; `type` = `application/vnd.ithilbert.ai-manifest-capability+json`; `data` = die bisherigen Capability-Felder (`id`, `method`, `path`, `summary`, `auth` nur wenn wahr, `params` nur wenn vorhanden, `mechanism` nur wenn gesetzt); kein `url`.
- **AK3 — representativeQueries:** Die Einträge nach AK2 haben 2 bis 5 `representativeQueries`: die per `->queries(['…', '…'])` (Fluent-Setter an der Route; im Generator der Schlüssel `queries`) angegebenen, höchstens fünf, nur nicht leere, ohne Dubletten; sind es danach weniger als zwei, gelten ersatzweise `displayName` und `"<METHOD> <path>"` (ohne Dubletten).
- **AK4 — Publisher und Namespace:** Config `publisher` (Standard `null`) bzw. ohne Wert der Host aus `config('app.url')` in Kleinbuchstaben ohne Port, ohne Host `localhost`; Config `namespace` (Standard `routes`). Jeder erzeugte `identifier` erfüllt `^urn:air:[a-zA-Z0-9.-]+(:[a-zA-Z0-9._-]+)+$`.
- **AK5 — Manuelle Einträge und leere Website:** Config `entries` (Liste, Standard `[]`) ergänzt Einträge: je Eintrag Pflicht `name` (wird `identifier` mit `urn:air:<publisher>:<namespace-manuell>:<name>`, Namespace-Teil aus Config `entries_namespace`, Standard `site`), `displayName`, `type` und genau eines von `url`/`data`; weitere Schlüssel des Schemas (`representativeQueries`, `description`, `tags` …) gehen unverändert durch. Ein Eintrag, dem Pflichtangaben fehlen oder der `url` und `data` zugleich hat, wird verworfen (kein Fehler). Ohne markierte Routen, Generatoren und Einträge liefert die Route `{"entries":[]}`.
- **AK6 — Schema-Validität:** Alle vom Paket aus Routen erzeugten Einträge erfüllen die Pflichten von `ard-entry.schema.json` (`identifier`-Muster, `displayName`, `type`, genau eines von `url`/`data`, `representativeQueries` als Liste von Zeichenketten).
- **AK7 — Übergangspfad:** Gegeben Config `ai_catalog_legacy` (Standard `true`, env `AI_MANIFEST_LEGACY_AI_CATALOG`) — Dann liefert `GET /.well-known/ai-catalog.json` denselben Body und Content-Type wie `ard.json` (Routenname `ai-manifest.ai-catalog`); mit `false` ist der Pfad 404.
- **AK8 — Link-Komponente:** Wenn `<x-ai-manifest::ard-link />` gerendert wird — Dann entsteht `<link rel="ard" href="<url('/.well-known/ard.json')>">` (absolute URL der App).
- **AK9 — llms.txt aus Datei oder Config:** Gegeben Config `llms_txt` mit `datei` (Pfad zu einer Markdown-Datei), sonst `inhalt` (String), sonst erzeugt aus `name`/`description` und `links` — Dann liefert `GET /llms.txt` Status 200, Header `Content-Type: text/plain; charset=utf-8` und den Inhalt; Vorrang `datei` > `inhalt` > erzeugt. Erzeugt: `# <Name>`, Leerzeile, bei gesetzter Beschreibung `> <Beschreibung>`, Leerzeile, `## Links` und je Eintrag aus `links` (`title`, `url`, optional `desc`) eine Zeile `- [title](url)` bzw. `- [title](url): desc`. Ist nichts davon vorhanden (kein `datei`, kein `inhalt`, keine `links`) oder die Datei nicht lesbar, ist die Antwort 404.
- **AK10 — Generate-Befehl:** `php artisan ai-manifest:generate` schreibt den Body von `ard.json` nach `public/.well-known/ard.json` (Option `--path` bleibt) und meldet die Zahl der Einträge; die Datei `ai-manifest.json` wird nicht mehr geschrieben.
- **AK11 — Cache:** `cache_ttl` gilt weiter für den ARD-Body (Schlüssel enthält den Fingerabdruck des Bodys); 0 = kein Cache; eine geänderte Capability erscheint nach dem Cache-Ablauf bzw. sofort bei geändertem Fingerabdruck.
- **AK12 — Altes Format entfernt:** Die Config-Schlüssel `version`, `auth`, `mechanisms`, `rate_limits`, `contact`, `public` und die Methode `AiManifestService::toArray()/toJson()/buildHead()` des alten Formats gibt es nicht mehr; die Config trägt die neuen Schlüssel (`publisher`, `namespace`, `entries_namespace`, `entries`, `ai_catalog_legacy`, `llms_txt`, bleibend `name`, `description`, `middleware`, `cache_ttl`). Der Enum `Mechanism` bleibt (Feld `mechanism` in `data`).
- **AK13 — Dokumentiert:** Die README beschreibt ARD-Route, Eintragsform, `->queries()`, Config-Schlüssel samt env-Namen und Standards, die Link-Komponente, llms.txt, Übergangspfad samt Rückbau-Bedingung, die Wahl für Firmen-Websites ohne API (leere Liste) und den Umstieg von 1.x auf 2.0 (was entfällt); Verweis auf Entscheidung 0001.
- **AK14 — Mindestens zwei Queries, gültige Namen und `data` (Ergänzt 2026-11-17, #1444 Punkt 1–3, selbst freigegeben):** (a) Bleiben nach AK3 weniger als zwei Queries, gelten als weitere Ersatzwerte der Reihe nach `id` und `path` (nur nicht leer, ohne Dubletten), bis es zwei sind; mehr als fünf bleiben ausgeschlossen. (b) Eine leere `id` (`->id('')`) fällt auf die Standard-`id` (Routenname, sonst `"<methode>:/<pfad>"`) zurück; ein Generator-Eintrag mit leerer `id` oder leerem `path` wird verworfen wie bei fehlendem Schlüssel; `displayName` ist dadurch nie leer. (c) Ein manueller Eintrag mit `data` als Liste (nicht assoziativ) wird verworfen wie bei fehlender Pflichtangabe; ein leeres `data` bleibt ein JSON-Objekt.

## Randfälle
1. Route mit `->aiManifest()` ohne Summary und ohne Namen: `id` wie bisher `"get:/pfad"`; im `identifier` werden `:` und `/` zu `-`.
2. Zwei Einträge mit gleichem `identifier`: der zweite bekommt `-2`, `-3` … angehängt (Eindeutigkeit).
3. `public/llms.txt` bzw. `public/.well-known/ard.json` als statische Datei: der Webserver liefert sie vor Laravel; das Paket ändert daran nichts (README nennt es).
4. `ai_catalog_legacy` und `middleware`: Der Übergangspfad hat dieselbe Middleware.

## Nicht-Ziele
`Agentmap:`-Zeile für robots.txt (optional im Task, entfällt: `rel="ard"` genügt Lighthouse), WebMCP, Signieren/TrustManifest, Registry-Anbindung, Versions-Tag (nur auf Ansage von Joerg).
